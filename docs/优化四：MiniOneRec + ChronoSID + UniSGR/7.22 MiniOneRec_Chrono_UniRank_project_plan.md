# MiniOneRec 项目一：Chrono-UniRank MiniOneRec 优化方案

## 一、项目目标

在当前 MiniOneRec Dual-SID 优化框架基础上，引入 ChronoSID
的时间建模思想和 UniSGR 的生成-排序联合优化思想。

核心研究问题：

> 当前生成式推荐系统中，Semantic ID Generator 与后续 Ranker
> 存在目标不一致问题。能否利用时间信息增强 SID 表示，并让 ranking
> supervision 反向优化 generator representation，从而提升 candidate
> recall 到最终 HR/NDCG 的转化效率？

最终目标：

1.  提升 MiniOneRec 的 item-level HR@20/NDCG@20；
2.  降低 candidate recall 与最终排序结果之间的损失；
3.  验证生成-排序联合训练是否优于传统 post-hoc rerank。

------------------------------------------------------------------------

# 二、当前 MiniOneRec 基线

当前系统：

Text-SID / CF-SID / SASRec-SID

↓

candidate generation

↓

candidate fusion

↓

history-aware rerank

↓

Top-K recommendation

主要问题：

1.  generator 只优化 SID generation likelihood；
2.  reranker 只负责后处理；
3.  rerank loss 无法影响 generator；
4.  union recall 已较高，但排序无法充分利用候选。

分四个阶段：

# Phase 1：加入 ChronoSID 时间增强

## 目标

验证时间信息是否能够提升 SID generator。

## 方法

当前输入：

history SID sequence:

\[v1_sid, v2_sid, ..., vL_sid\]

修改为：

\[g1, v1_sid, g2, v2_sid, ..., gL, vL_sid\]

其中：

g_i 表示相邻交互时间间隔。

## 时间桶

建议：

-   \<1h

-   1h-1d

-   1d-1w

-   1w-1mo

-   =1mo

增加 special tokens。

## 损失

保持原始：

L_gen

比较：

Baseline:

SID only

vs

SID + gap token

指标：

-   HR@20
-   NDCG@20
-   SID hit rate
-   invalid SID rate
-   candidate recall

------------------------------------------------------------------------

# Phase 2：增加共享 Ranking Head

## 目标

验证 generator hidden representation 是否可以用于排序。

## Candidate 构造

候选：

C={positive item}+hard negatives

hard negatives 来源：

-   Text beam candidates；
-   CF beam candidates；
-   SASRec candidates；
-   当前 reranker 排名前错误候选。

## Candidate representation

对候选 SID 使用 teacher forcing：

输入：

history + candidate SID

获得：

decoder hidden states。

candidate embedding：

z_uv = mean(hidden states)

## Ranking head

MLP:

score = Rank(z_uv)

Loss:

listwise softmax loss:

L_rank

------------------------------------------------------------------------

# Phase 3：Generation-Ranking Joint Training

## 核心思想

借鉴 UniSGR：

共享 generator hidden representation。

总损失：

L = L_gen + alpha L_rank

其中：

L_gen:

保证 SID generation 能力。

L_rank:

提供最终推荐目标监督。

梯度：

ranking loss

↓

shared decoder

↓

generator

使生成模型学习：

哪些 SID 不仅语义合理，而且最终推荐价值更高。

------------------------------------------------------------------------

# Phase 4：Rank-to-Generation Alignment（增强方向）

进一步加入：

generator probability distribution:

p_G(v\|u)

ranking distribution:

p_R(v\|u)

加入：

KL(p_R \|\| p_G)

目标：

让 generator 的 beam probability 更接近最终排序偏好。

# 五、实现原则

第一阶段不要引入：

-   MoE；
-   VA-PMTP；
-   Task-aware Token；
-   STARK；
-   tokenizer重新训练。

原因：

首先验证核心 insight：

> ranking supervision 是否能够改善 generative retrieval。
